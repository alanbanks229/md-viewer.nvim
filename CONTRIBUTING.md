# Contributing

Thanks for helping improve `md-viewer.nvim`.

Before opening a change, check existing issues and keep proposals within the
documented security and process boundaries. For behavioral changes, include a
focused test or explain why the behavior can only be verified interactively.

## Pull requests

1. Create a topic branch from `main`.
2. Install dependencies and run the commands in
   [docs/development.md](docs/development.md).
3. Keep generated dependencies, browser binaries, logs, screenshots, and local
   machine configuration out of commits.
4. Update user documentation and `CHANGELOG.md` when behavior changes.
5. For graphical changes, name the OS, terminal (and version), Neovim, Node.js,
   and browser versions you tested on. See the manual verification checklist in
   [docs/development.md](docs/development.md) for what to check, and
   [docs/terminal-support.md](docs/terminal-support.md) for per-terminal status.
