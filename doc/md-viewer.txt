INTRODUCTION                                                     *md-viewer*

md-viewer.nvim renders unsaved Markdown source in a persistent headless
Chrome or Chromium page, captures the visible viewport as a PNG, and places
that raster image over a read-only Neovim preview split.

The preview is still a browser-rendered PNG surface, not native terminal
text and not a real embedded webview. Mouse and keyboard interaction over
the preview (|md-viewer-interaction|) is forwarded to the persistent
Chromium DOM, which performs hit-testing, selection, search, and link
resolution before the viewport is recaptured — this provides browser-like
behavior, but it is a raster surface with synthetic interaction layered on
top of it, not real terminal selection. Source text remains a normal,
separately editable and selectable Neovim buffer throughout.

The renderer opens no external browser window, starts no HTTP server, and
listens on no localhost port. Runtime browser network requests are blocked by
default.

=============================================================================
REQUIREMENTS                                         *md-viewer-requirements*

- Neovim 0.12+
- Node.js 22.12+
- an existing Chrome, Chromium, or Microsoft Edge installation
- a terminal that advertises the Kitty graphics protocol, used without a
  multiplexer -- see |md-viewer-terminals|
- locked renderer dependencies installed with npm ci

Playwright browser downloads are intentionally disabled. See README.md for
plugin-manager installation and the required renderer build hook.

SETUP                                                       *md-viewer-setup*

Minimal configuration for a terminal that advertises Kitty graphics: >lua

    require("md-viewer").setup({
      image = { backend = "kitty_raw" },
    })
<
The complete defaults are documented in README.md and
lua/md-viewer/config.lua. Important option groups are:

    split       Preview position and size
    preview     Pinning, winbar, and loading indicator
    render      Markdown, scale, quality, and scroll behavior
    browser     Existing browser executable and launch timeout
    image       Graphical or cell backend and placement behavior
    sync        Source-following and preview navigation
    security    Runtime network policy and local document root
    terminal    Terminal profile detection and capability overrides
    interaction Mouse/keyboard interaction: selection, search, links

Optional exact terminal cell sizes use MD_VIEWER_CELL_WIDTH_PX and
MD_VIEWER_CELL_HEIGHT_PX.

                                              *md-viewer-overlay-alignment*
With the kitty_raw backend the terminal draws the image, and a notification
floating over the preview has its rectangle cut out of it so it keeps its own
background. Some terminals apply their horizontal window margin to text but not
to graphics placements, which draws the image a fraction of a cell toward the
origin and leaves that cut slightly misaligned. Two image options handle it:

    raw_overlay_bleed_cells   Extra columns cut past a notification's
                              trailing edge so the overhang cannot paint
                              across it. Default 1.
    raw_cell_offset_px        Pixel offset at which the image starts inside
                              its first cell, as the Kitty protocol's X/Y
                              placement keys. Cancels the misalignment
                              outright where the terminal implements them.
                              Default { x = 0, y = 0 }.

:MdViewerHealth reports both. See README.md for how to measure the offset,
and docs/manual-testing.md for the per-terminal alignment matrix.

COMMANDS                                                 *md-viewer-commands*

                                                            *:MdViewerOpen*
:MdViewerOpen [position]
        Open a preview. Position can be right, left, below, or above.

                                                           *:MdViewerClose*
:MdViewerClose
        Close the active preview and remove its owned image.

                                                          *:MdViewerToggle*
:MdViewerToggle [position]
        Open or close the active preview.

                                                         *:MdViewerRefresh*
:MdViewerRefresh
        Force a fresh render of the active preview.

                                                            *:MdViewerCopy*
:MdViewerCopy
        Copy the current preview selection to the unnamed register, and to
        the system clipboard register when one is configured. A clean
        notification, not an error, when nothing is selected.

                                                 *:MdViewerClearSelection*
:MdViewerClearSelection
        Clear the current preview selection without clicking.

                                                            *:MdViewerFind*
:MdViewerFind [query]
        Search the rendered preview for `query`. Prompts for a query via
        |vim.ui.input()| when none is given.

                                                        *:MdViewerFindNext*
:MdViewerFindNext
        Jump to the next search match.

                                                    *:MdViewerFindPrevious*
:MdViewerFindPrevious
        Jump to the previous search match.

                                                       *:MdViewerFindClear*
:MdViewerFindClear
        Clear the active search and its highlighting.

                                                            *:MdViewerBack*
:MdViewerBack
        Return the preview to the previous document in its history, moving
        the source window with it. See |md-viewer-history|.

                                                         *:MdViewerForward*
:MdViewerForward
        Move the preview to the next document in its history, after going
        back.

                                                          *:MdViewerHealth*
:MdViewerHealth
        Open a concise health summary: overall status (healthy/degraded/
        broken), the selected rendering backend, and any actionable
        warnings. Round-trips to the renderer subprocess.

:MdViewerHealth verbose
        Open the full field-by-field diagnostic report -- raw graphics
        geometry, terminal-profile evidence, and Chromium session state
        (which document is currently active, cached document/frame
        counts) -- useful for bug reports and troubleshooting. See
        |md-viewer-health|.

                                                           *:MdViewerDebug*
:MdViewerDebug
        Open session, renderer, timing, selection/search, and placement
        diagnostics. Selection and search state is reported as lengths and
        counts only -- the selected text and search query content are
        never printed here.

PREVIEW NAVIGATION                                   *md-viewer-navigation*

The graphical preview maps these Normal-mode keys:

    j, k, Down, Up           One rendered line
    CTRL-E, CTRL-Y           One rendered line
    CTRL-D, CTRL-U           Half a viewport
    CTRL-F, CTRL-B           Approximately one viewport
    PageDown, PageUp         Approximately one viewport
    gg, G                    Document top or bottom
    H, L                     Back/forward through the preview history
                             (|md-viewer-history|)
    y                        Copy the current selection (:MdViewerCopy)
    /                        Prompt and search (:MdViewerFind)
    n, N                     Next/previous search match

Mouse-wheel events scroll the preview only when the pointer is over its split.

MOUSE INTERACTION                                    *md-viewer-interaction*

Every gesture below is dispatched through the `interact` transport to the
live Chromium DOM -- see |md-viewer| for what that means and does not mean.
Each is gated by its own `interaction.*` config flag.

    Click and drag        Selects the dragged text (a real DOM selection)
    Plain click            Clears an active selection; never moves the
                            source cursor, whether or not anything was
                            selected
    Double-click            Selects the word under the pointer
                            (`interaction.word_select`)
    Triple-click             Selects the enclosing paragraph/block
                            (`interaction.paragraph_select`)
    CTRL-click / CMD-click  Activates a link under the pointer: opens
                            http(s)/mailto externally, opens an in-root
                            local file, or scrolls to a same-document
                            fragment. Refuses an unsafe scheme or a
                            document-root escape, with a notification. Does
                            nothing over non-link text.

A local Markdown link opens in Neovim, in the source window, and the preview
follows it; CTRL-O returns. Files Neovim has no filetype for, and PDFs, still
go to the system handler. On macOS the terminal itself may claim CTRL-click or
CMD-click before Neovim sees it -- check the terminal's mouse settings if
neither activates a link.

The document root a local link is checked against defaults to the project
enclosing the document (nearest ancestor holding `.git`, `.hg`, or `.svn`),
falling back to the document's own directory. Set `security.document_root` to
pin it, or `security.document_root_markers` to change what identifies a
project.

Copying is always manual (`y` / :MdViewerCopy) unless
`interaction.copy_on_select = true` is set, which is off by default.

                                                        *md-viewer-history*
GOING BACK AND FORTH ~

Following a link retargets the preview, and `preview.pinned` deliberately
stops the preview following an ordinary buffer switch -- so without a way
back, the document the reader came from is only recoverable as text, never as
a rendered view.

    H  / :MdViewerBack       Previous document in this preview's history
    L  / :MdViewerForward    Next document, after going back

H and L are preview-local, installed beside the keys the preview already owns
(`y`, `/`, `n`, `N`, `gg`, `G`), and shadow "top/bottom of screen" -- which
addresses nothing in a scratch buffer holding no text. They are gated on
`interaction.links`, since a link activation is the only thing that ever puts
a second document in the history. Both commands work from either window.

All of them move the source window as well, for the same reason activating a
link does. CTRL-O works on its own too: when the source window returns to a
document this preview has already shown, the preview follows it back.
Deliberately narrow -- only documents in this preview's own history qualify,
so `preview.pinned` still holds for every other buffer switch.

Navigating from the middle of the history abandons the forward branch, the
same rule a browser follows. The list is capped at
`interaction.history_limit` (default 32) and records a buffer and a path per
entry, so an entry whose buffer has been wiped still reopens its file.

The mouse pointer never changes shape over the preview. The preview is a PNG,
so only the terminal could change it (OSC 22), and support is inconsistent
enough across terminals that the result was worse than no feedback at all.
Nothing is sent, and the global 'mousemoveevent' is left alone.

TERMINAL SUPPORT                                        *md-viewer-terminals*

md-viewer.nvim recognizes iTerm2, Kitty, WezTerm, Ghostty, and Warp by
Kitty-graphics-protocol compatibility. Only iTerm2, Ghostty, Kitty and
WezTerm have real historical, human-observed confirmation, and mostly for
image rendering and the drag-to-highlight overlay; the other interaction
features are graphically unvalidated on every terminal as of this writing.
See docs/manual-testing.md for the full scenario matrix and the four honest
status labels it uses.

The instant drag highlight -- the selection drawn as translucent overlay
rectangles rather than re-photographing the page each frame -- is enabled on
iTerm2, Ghostty and Kitty, each of which an operator drove by hand and
watched across repeated drags. It is off on WezTerm for cost rather than
correctness: its geometry was photographed correct on both the 20240203
stable and a current build, using an encoding md-viewer sends WezTerm alone,
but sustained placement traffic grows the terminal's memory without bound --
172 MB to 786 MB in four seconds with four rectangles. See the 2026-08-08
section of docs/cross-platform-implementation-status.md. Everywhere else the
drag falls back to full captured frames -- always correct, merely slower. Set
`interaction.selection_overlay` to "on" (see |md-viewer-setup|) to qualify
your own terminal, after reading that option's notes in lua/md-viewer/
config.lua. :MdViewerHealth verbose (see |md-viewer-health|) reports whether
the overlay is in use, why, and the layer it draws on.

tmux, screen, and Zellij are not supported: no escape-sequence passthrough
is implemented for any of them. :MdViewerHealth detects a multiplexer and
surfaces it as a warning so the failure is diagnosable.

=============================================================================
SECURITY                                                 *md-viewer-security*

The default renderer blocks runtime browser networking, disables browser
JavaScript, rejects remote images, disables raw Markdown HTML, and confines
local images to a canonical document root. Initial npm ci installation may
contact the configured npm registry.

Mouse/keyboard interaction adds no new attack surface: every gesture
resolves against the same already-sanitized document (nothing re-parses
Markdown or re-touches the filesystem on a click or a drag), local-file link
activation re-checks the document root the same way image loading does
(symlinks included), and search/selection text is always handled as plain
text, never interpreted as markup.

See docs/security.md and SECURITY.md before enabling security.network or
render.raw_html.

=============================================================================
HEALTH                                                     *md-viewer-health*

Run: >vim

    :checkhealth md-viewer
    :MdViewerHealth
    :MdViewerHealth verbose
    :MdViewerDebug
<
`:checkhealth md-viewer` and the default `:MdViewerHealth` both give a
concise summary -- an overall status (healthy/degraded/broken), the
selected backend, and any warnings. `:MdViewerHealth verbose` adds the
full field-by-field diagnostic detail (raw graphics geometry, terminal
evidence, Chromium session state) without changing what was collected.

Graphical pixel correctness, click accuracy, and interaction behavior still
require direct interactive terminal testing; a headless health check cannot
validate terminal rendering, real mouse input, or flicker.
